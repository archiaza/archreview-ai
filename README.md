## Что такое ArchReview AI

ArchReview AI — система, которая читает проектную документацию и возвращает структурированный перечень замечаний со ссылками на конкретные пункты нормативных документов.

На вход подаётся раздел проектной документации, на выходе — балл качества, экспертное резюме и список выявленных нарушений с указанием норматива, серьёзности и рекомендации по исправлению.

## Какую проблему решает

Нормоконтроль проектной документации сегодня выполняется вручную. Это создаёт три системные проблемы:

- **Долго.** Проверка одного раздела занимает часы экспертного времени.
- **Непоследовательно.** Два специалиста находят разные замечания в одном и том же комплекте.
- **Дорого.** Ошибка, пропущенная на этапе проектирования и найденная на стройке, обходится в десятки раз дороже.

Нормативная база (СП, ГОСТ, СанПиН, федеральные законы) объёмна и регулярно обновляется — удерживать её в голове целиком невозможно.

ArchReview AI переводит первичный нормоконтроль в автоматический режим: эксперт получает готовый перечень замечаний и тратит время на проверку и решение, а не на поиск.

## Основной сценарий

```
1. ЗАГРУЗКА
   Пользователь загружает раздел проектной документации
   (PDF / DOCX) либо вставляет фрагмент текста.
   Выбирает раздел ПД и критерии проверки.
                    ↓
2. ИЗВЛЕЧЕНИЕ
   Система извлекает текстовое содержание документа
   и приводит его к виду, пригодному для анализа.
                    ↓
3. AI-АНАЛИЗ
   Содержание передаётся в LLM-пайплайн, который
   сопоставляет проектные решения с требованиями
   нормативной базы.
                    ↓
4. ПРОВЕРКА
   Выявленные несоответствия классифицируются
   по серьёзности и привязываются к конкретным
   пунктам НТД.
                    ↓
5. ЗАМЕЧАНИЯ
   Формируется структурированный перечень:
   раздел · заголовок · описание · норматив · severity
                    ↓
6. РЕЗУЛЬТАТ
   Балл качества 0–100, экспертное резюме,
   выгрузка отчёта в Word / JSON / Markdown.
```

## Текущий статус

**Working MVP** — система работает и используется для проверки реальных разделов проектной документации.

Реализовано и функционирует:

- ✅ Загрузка документов и ручной ввод текста
- ✅ Извлечение текста из PDF и DOCX
- ✅ LLM-анализ с привязкой замечаний к нормативам
- ✅ Классификация замечаний по серьёзности
- ✅ Расчёт интегрального балла качества
- ✅ Генерация отчёта в Word (.docx)
- ✅ Выгрузка в JSON и Markdown
- ✅ Демонстрационный режим без подключения к LLM

## Ограничения текущей версии

Раздел приведён сознательно: границы применимости проверены тестами и известны.

| Ограничение | Текущее поведение |
|---|---|
| Объём PDF | Обрабатываются первые **30 страниц** документа |
| Таблицы в DOCX | Извлекается текст абзацев; содержимое таблиц не разбирается |
| Формат `.doc` | Не поддерживается — требуется конвертация в `.docx` или PDF |
| Чертежи и графика | Анализ графических материалов в разработке |
| Привязка к странице | Замечание ссылается на норматив, но не на номер листа |
| Сканы без текстового слоя | OCR не выполняется |

## Возможности

**Проверка по разделам проектной документации**
АР, КЖ, КМ, ОВ, ВК, ЭС, ПБ, МГН, ПЗ, СПОЗУ, ПОС, ООС, СМ, ТХ

**Настраиваемые критерии**
Соответствие нормам (СП, ГОСТ, СНиП) · Полнота состава ПД · Пожарная безопасность · Доступность МГН · Конструктивная безопасность · Экологические требования · Градостроительные регламенты · Сметная документация

**Классификация замечаний**

| Уровень | Значение |
|---|---|
| 🔴 `critical` | Нарушение обязательных требований |
| 🟡 `warning` | Несоответствие рекомендуемым нормам |
| 🔵 `info` | Замечание к оформлению |

**Балл качества 0–100**

| Диапазон | Интерпретация |
|---|---|
| 90–100 | Соответствует требованиям |
| 70–89 | Незначительные замечания |
| 50–69 | Существенные замечания |
| < 50 | Критические нарушения |

**Форматы выгрузки**
Word (.docx) — оформленный отчёт с таблицей показателей и перечнем замечаний · JSON — для интеграции · Markdown — для документации
